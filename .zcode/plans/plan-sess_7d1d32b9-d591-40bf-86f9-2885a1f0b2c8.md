# 场景壁纸：Godot 编辑器 fork + 内嵌运行时 + 权限沙箱

状态：2026-09-27 架构确认，接手并取代原「3D 壁纸场景编辑器（WinUI + scene.json）」方案。
关联：`docs/superpowers/specs/2026-09-25-wallpaper-backends-design.md`（其"不做可视化编辑器"边界已被本方案取代）。

## 已确认决策

| 项 | 决定 |
|---|---|
| 编辑器 | 基于 **Godot 4.7.2 源码 fork**，随桌面贴纸交付给最终用户 |
| 编辑器第一版功能 | **壁纸场景模板 + 导出前校验 + 自定义「导出壁纸包」入口**；场景内容用 Godot 全量节点/功能创作 |
| 创作到应用流程 | 编辑器导出**壁纸包文件** → 桌面贴纸设置页**手动导入** → 选中应用 |
| 运行时 | 同一 fork 编译出的 **Godot 运行时库**，内嵌在壁纸模块进程内；用户机器无外部 Godot 程序、无需安装 |
| 呈现 | **深度改造 Godot 呈现层：直接复用现有壁纸窗口**（WorkerW 子窗口）；不新建 Godot 窗口、不用外部进程 |
| 脚本安全 | **默认沙箱**（引擎内置权限层）+ 壁纸设置页「全局默认 + 单壁纸覆盖」逐项授权 |
| 引擎能力边界 | 尽量保留 Godot 全部语义（GDScript/物理/动画/粒子/材质等原样可用） |

## 壁纸包格式（`.dswall`，ZIP 容器）

```
xxx.dswall
├─ project.pck      # Godot 导出包（场景/脚本/资源）
├─ manifest.json    # 标题、作者、主场景、格式版本、引擎版本指纹、请求的能力清单
└─ poster.png       # 缩略图（编辑器导出时抓帧）
```

- 导入时**不依赖 Godot** 即可读出元数据与海报；
- 运行时由内嵌运行库加载 `project.pck`；
- 引擎版本指纹不匹配 → 拒绝并有明确提示，不黑屏。

## 引擎 fork（固定 Godot 4.7.2-stable）

- **宿主 API（embed）**：外部 HWND + 尺寸、tick 驱动、暂停/恢复、静音、加载 pack/项目目录、权限提供者注入。
- **DisplayServer 补丁**：接受外部 HWND；不创建/不管理自己的窗口样式；`VkSurface` 直接建在现有壁纸窗口上；不抢输入焦点。
- **权限层**（开发期即引入）：网络 / 包外文件读写 / 执行外部程序 / 系统访问；GDExtension 编译期关闭；未授权调用返回失败并记录，可供设置页展示。
- **构建**：VS2022 + SCons，产出「编辑器」与「壁纸运行库」两个目标；工具脚本沿用 `prepare_*.ps1` 纪律（固定版本、哈希校验、gitignore、缺负载降级）。

## 与桌面贴纸的集成

- 作为新的自呈现后端：`PresentationArbiter` 让位（撤空 DComp visual），运行库在壁纸窗口上呈现。
- 暂停策略沿用三项（手动/全屏遮挡/锁屏息屏）：暂停 = 停止引擎迭代（0 CPU/GPU），恢复继续。
- 音频受现有全局静音/音量控制（默认静音）；分辨率跟随显示器（含 DPI 变化）；仅主显示器；保持点击穿透、不可交互。
- 失败处理：包损坏/版本不符/权限拒绝 → 回落上一可用壁纸并记日志；失败标记避免下次自动重载同包。
- 旧外进程 `GodotBackend` 在内嵌路径可用后删除。

## 里程碑

### M1 内嵌运行库最小验证（✅ 已完成）
1. Godot 4.7.2 源码 **vendoring 进仓库**（`tools/godot-src/`），构建脚本 `tools/build_godot.ps1`（RuntimeLib / Editor）；
2. `dstk_*` 宿主 API + 外部 HWND 呈现补丁（fork 改动直接入库，不再维护补丁集）；
3. 宿主测试 `tools/godot-host-test/`：加载项目/包 → WorkerW 子窗口呈现 → F8/F9 暂停恢复 → F10 退出并恢复桌面壁纸；
4. 实测：渲染正常（自呈现节拍 60Hz），**全程无外部 Godot 进程**。

### M2 编辑器 fork（✅ 已完成）
- 模板工程升级 4.7（关闭无障碍）+ `addons/dstk_wallpaper/`：场景校验 + 导出 `.dswall`
  （`project.pck` + `manifest.json` + `poster.png`，走 `--export-pack`，不依赖导出模板）；
- 宿主 `--dswall` 加载导出包端到端成功。

### M3a 导入/加载/渲染与切换（✅ 已完成）
- `.dswall` 导入：复制原包 + `tar.exe` 解包到 `media/<id>/shader/` + 海报提到条目根 + manifest 标题；
- `GodotEngineHost` + `GodotEmbeddedBackend`：进程级单例引擎、自建 WorkerW 呈现窗口（先隐藏→注册→再显示）、
  `dstk_godot_load_pack` 运行中换包；
- 视频 ↔ 场景 ↔ Vulkan 内置场景来回切换、退出恢复桌面壁纸；
- 处置两个既有问题：① NVIDIA 驱动 `vkDestroy*` 间歇性闪退/挂起 → Vulkan 设备**寄存 + 复用**
  （`Impl::reinit_scene`，不再二次创建交换链，也不做驱动销毁）；② 暂停清屏变黑 → 暂停保留最后一帧。

### M3b 权限机制（下一步）
- 引擎 fork 权限层（网络 / 包外文件读写 / 执行外部程序 / 系统访问，默认拒绝）；
- manifest `requested_permissions` + 设置页「全局默认 + 单壁纸覆盖」授权；越权调用报错并记录。

### M4 打磨与验收
- 文档、第三方声明（已加 Godot MIT）、工具链脚本、人工验收清单；
- 已知遗留：ResMon 内存页未识别 Godot 运行库为自有模块；场景壁纸音频未接全局静音；限帧/功耗策略未做。

## 被取代/暂缓

- 原计划的 WinUI `SceneEditorController`、`scene.json` scene3d 多物体可视化编辑——被本方案取代；
- 既有 Vulkan 内置场景与其它后端（视频/动图/序列/Web）保持不变。

## 风险

| 风险 | 对策 |
|---|---|
| 引擎源码级呈现改造（DisplayServer/主循环集成） | M1 已验证可行；窗口创建封装在 `GodotEngineHost`，失败可退回顶层窗口 |
| fork 维护成本 | 固定 4.7.2 并 vendoring 进仓库；构建脚本可重复；fork 改动有注释与 AGENTS.md 记录 |
| 本机 NVIDIA 驱动 Vulkan 销毁路径不稳定（既有问题） | 设备寄存 + 复用（`reinit_scene`）；绝不二次创建交换链；见 AGENTS.md 脆弱区 |
| 用户脚本安全/稳定性 | 默认沙箱 + 权限授权 + 失败标记；崩溃随进程（既有进程内 DLL 取舍） |
| 编辑器体积/分发 | 随应用交付，安装包与更新策略在 M3b/M4 明确 |
